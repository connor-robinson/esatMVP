### TEMPLATE: always_sometimes_never (AUTHORITATIVE)

Use when the schema naturally supports classifying a claim’s truth status across a domain.

#### Required stem structure
- Provide a claim about an object (number/expression/function) under a stated domain.
- Ask whether the claim is:
  - always true
  - sometimes true
  - never true
(Or an equivalent phrasing with “for all / for some / for no”.)

#### Option form
- Options are exactly:
  - A: Always true
  - B: Sometimes true
  - C: Never true
(You may add D–E only if you’re classifying two claims at once, but prefer single-claim.)

#### Distractor requirements
Common pitfalls:
- assuming “true for many cases” means always true
- missing boundary cases
- domain errors (e.g., forgetting x>0 for logs)
- confusing “sometimes” with “exists” incorrectly

#### Constraint
Must be solvable without brute force; should collapse via one key observation/counterexample.
