### TEMPLATE: counterexample_disproof (AUTHORITATIVE)

You must implement the Designer plan around **disproof / counterexample** reasoning.

#### Required stem structure
- Present a general claim (often “for all …” style) or a student assertion.
- Ask one of:
  - “Which option provides a counterexample?”
  - “Which option shows the claim is false?”
  - “Which criticism is valid?” (re: using examples to ‘prove’)
- The maths should be simple enough that validating a counterexample is quick.

#### Option form
Two allowed forms:

A) Counterexample candidates:
- Options are candidate values/objects.
- Exactly one is a valid counterexample.

B) Reasoning critiques:
- Options are short statements about why the argument is invalid.
- Exactly one critique correctly identifies the flaw.

Pick the form that best matches the Designer wrong paths.

#### Distractor requirements
Wrong options should include:
- near-misses that don’t actually violate the claim
- values outside the domain
- values that break a different condition (not the claim)
- “examples prove” fallacy variants (for critique-style)

#### Constraint
State the domain clearly and ensure checking each option is not computationally heavy.
