#### 1) **SIBLING mode** (Paper 2) — same schema, different instantiation

Goal: preserve the **same schema invariant reasoning move**, but change the surface so it cannot be answered by recalling the reference.  
Treat these rules as **strong guidance**, not a ceiling — be creative while staying on-syllabus and faithful to the schema.

### What must stay the same
- **Same dominant schema invariant** (one core reasoning move; no stacking).
- **Same reasoning direction** in the deep sense (e.g. “spot invalid inference”, “negate a quantified claim”, “necessary vs sufficient”), even if the question wrapper changes.
- **Comparable effort band** to the reference (similar mental load / line-count / reasoning length).
- **Paper 2 focus**: the bottleneck is **inference**, not algebra grind.

### What must change (change at least 3, or invent equivalents)
You should change multiple “surface levers” while preserving the invariant:

**A) Template lever (Paper 2 surface)**
- Switch among close Paper 2 templates *without changing the invariant*:
  - “which statement(s) must be true” ↔ “which statement(s) could be true”
  - “necessary/sufficient” ↔ “if / only if / iff” phrasing
  - “first error line” ↔ “which step is unjustified” (still error-spotting)
  - “counterexample” ↔ “why examples don’t prove” (still disproof reasoning)

**B) Statement framing**
- Replace explicit conditions with logically equivalent wording:
  - “for all” ↔ “no counterexample exists”
  - “there exists” ↔ “at least one example”
  - implication wording variants: “A only if B”, “A if B”, “A implies B”
- Change whether claims are presented as:
  - a student’s argument, or
  - a list of claims I/II/III, or
  - conditions (I)–(III) about an object.

**C) Mathematical domain wrapper (lightweight)**
- Keep the maths within Section 1, but vary the wrapper:
  - integers / parity ↔ algebraic expressions ↔ simple functions ↔ geometric constraints ↔ probability statements
- The maths should remain **simple enough** that logic remains central.

**D) Trap / wrong-path identity**
- Keep the same *type* of mistake, but change how it appears:
  - converse vs contrapositive confusion
  - negating quantifiers incorrectly
  - confusing necessary with sufficient
  - assuming cancellation when a factor may be zero
  - treating examples as proof
  - missing a boundary/case that breaks an argument

**E) What is asked**
- Change the ask while keeping the invariant:
  - “which option identifies the first error?” ↔ “which statement justifies line (IV)?”
  - “which condition is sufficient?” ↔ “which condition is necessary?”
  - “which claim is false?” ↔ “which claim is not guaranteed?”

### How different should it feel?
- A strong candidate should think: **“same reasoning move, new skin.”**
- It should not feel like “same question with new numbers”.
- The same invariant should still be the reason the correct option is correct.

### What SIBLING must NOT do
- Do not keep the same argument skeleton / same labelled-line structure with only cosmetic edits.
- Do not copy distinctive phrasing or the reference’s “signature” setup.
- Do not introduce a second deep idea to raise difficulty.
- Do not convert it into a Paper 1 computation problem unless the schema explicitly requires it.
