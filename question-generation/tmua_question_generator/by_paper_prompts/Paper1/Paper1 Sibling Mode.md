#### 1) **SIBLING mode** (same schema, different *instantiation*)

Goal: the candidate must perform the **same core reasoning move** as the reference, but they should not be able to “spot-and-recall” the original.

**What must stay the same**

* **Same dominant schema move** (the “one thing” the question tests).
* **Same difficulty band** as the reference (similar mental load / step count).
* **Same no-calc friendliness**: engineered simplifications, clean exact values.

**What MUST change**
You change *at least 3* of these “surface levers”, or invent your own:

* **Object class**: polynomial ↔ rational ↔ trig ↔ logs/indices ↔ sequences ↔ coordinate geometry, etc. (still within the schema).
* **Constraint type**: “touches axis” ↔ “has repeated root” ↔ “two intersections” ↔ “exactly one solution” ↔ “sum/product of roots” (same underlying condition).
* **What is asked**: find a parameter ↔ count solutions ↔ find a maximum/minimum ↔ determine range ↔ identify which statement is true.
* **Representation**: purely algebraic ↔ graph/intersection framing ↔ geometric interpretation (but no diagram).
* **Direction of reasoning**: instead of compute output given parameter, solve for parameter given desired behaviour.
* **Domain twist** (still fair): restrict to integers / positive reals / an interval / degrees vs radians (if trig), but not “gotcha”.

**How “different” should it feel?**

* A strong student should say: *“Same kind of thinking… but not the same question.”*
* If the reference is “discriminant = 0”, the sibling might use “tangent intersection”, “double root”, or “line of symmetry + ‘touches axis’” as the *presentation*, but it’s still the discriminant/double-root schema underneath.

**What SIBLING must NOT do**

* Don’t keep the same stem skeleton and just swap numbers.
* Don’t preserve distinctive constants/structure from the reference.
* Don’t add extra schemas to make it “harder”; difficulty comes from the sibling disguise, not stacking concepts.
